2-1. 業務の構造的理解

覚えること

  • AIエージェント導入はツール選定から始まらない。業務構造の理解から始まる
  • 3階層の区別:
    • 仕事: 組織や個人が果たすべき目的・役割の全体
    • 業務: 仕事を実現するために組織が繰り返し行う一連の流れ
    • 作業: 業務を構成する具体的な行為
  • AIエージェントが直接置き換えるのは「作業」だが、前後の流れを把握しないと適切な設計はできない
  • IPOモデル: Input（入力）/ Process（処理）/ Output（出力）の3要素で業務を捉える
  • As-Is分析: 業務の「現在の姿」をIPO構造で事実だけ記録（改善案を混ぜない）
  • To-Be分析: 業務の「あるべき姿」を設計
  • ギャップ分析: As-IsとTo-Beの差分を明確化

As-Is分析の具体的手法

  • プロセスウォークスルー: 実際の作業を横で観察・記録（ヒアリングだけに頼らない）
  • 5W1Hヒアリングシート: Who/What/When/Where/Why/How
  • スイムレーン図: 部署横断業務の可視化
  • マニュアルと実態の差分確認: マニュアル≠実態
  • タイムスタディ: 各作業の実測

試験頻出ポイント

  • As-Is分析の段階で改善案を混ぜない（事実の把握と改善議論の混在を避ける）
  • 「Why」が答えられない工程は廃止候補
  • 順序: As-Is → To-Be → ギャップ分析 を厳守

2-2. BPR（業務改革）の基礎

覚えること

  • BPR（Business Process Reengineering）: 既存業務を漸進的改善ではなく、根本から問い直して再設計する手法
  • 「改善（Improvement）」と「再設計（Reengineering）」は発想の出発点が異なる
  • 「汚いプロセスの自動化」の罠: 非効率な業務をそのまま自動化すると、非効率を高速で回す装置になるだけ
  • ハマーの言葉: 「既存のプロセスを自動化することは、既存の問題を自動化すること」
  • AIエージェントが高性能であるほどこの罠の影響は大きい

ECRS原則（効果の大きい順）

  • Eliminate（排除）: 「この業務は存在すべきか」を問う → 最も効果大
  • Combine（結合）: 「分かれている理由はあるか」
  • Rearrange（順序変更）: 「この順序に根拠はあるか」
  • Simplify（簡素化）: 「これ以上削ぎ落とせないか」

試験頻出ポイント

  • 順序はEから検討。排除できれば自動化すら不要
  • BPRは「全部作り直す」ではなく「プロセスの存在意義を問い続ける姿勢」
  • 順序: As-Is → BPR（ECRS）→ To-Be 設計

2-3. 業務可視化の手法

覚えること

  • 暗黙知の罠: 熟練者の判断・手順は本人も言語化できないことが多い
  • 4つの可視化手法（粗→細）:
    • IPOモデル: Input・Process・Outputの3要素で業務の輪郭を掴む
    • SIPOC分析: Supplier・Input・Process・Output・Customer。関係者まで洗い出す
    • HTA（Hierarchical Task Analysis）: 階層的タスク分析。アトミック・タスクまで分解
    • 業務フロー図（スイムレーン図）: 最も詳細な可視化。チームの認識統合に最適

4手法の使い分け

  • 全体像を経営層に説明 → IPO + SIPOC
  • AIと人間の役割分担を現場と詰める → HTA + 業務フロー図
  • 必ず全部を使う必要はない。目的に応じて選択

HTAでのアトミック・タスク3分類

  • AIエージェント処理: ルールが明確で繰り返し発生
  • 定型処理（RPA・スクリプト）: 判断を伴わない機械的操作
  • 人間が担う: 例外判断・倫理判断・高度な文脈理解

試験頻出ポイント

  • SIPOCのCustomer洗い出しで「出力受取者の見落とし」を防ぐ（後からの追加要件防止）
  • HTAはHuman-in-the-Loop設計と直接つながる
  • 業務フロー図の価値は「チームの認識統合」

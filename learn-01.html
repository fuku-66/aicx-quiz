1-1. 生成AIの基礎

覚えること

  • AIの3フェーズ: ①作るAI（〜2022年・専門家が作る）/ ②使うAI（2022年〜・ChatGPT以降・誰もが使う）/ ③任せるAI（2024年〜・AIエージェント時代）
  • AGI（汎用人工知能）とASI（人工超知性）は不確実性の高い長期シナリオとして冷静に参照する
  • 生成AI: 学習データから新しいテキスト・画像・音声等を生成。最大インパクトは「非構造化データの活用」（企業データの80%以上）
  • 機械学習の3手法: 教師あり学習 / 教師なし学習 / 強化学習
  • ディープラーニング: ニューラルネットワークを多層化。最大の進歩は「特徴量の自動抽出」
  • LLM（大規模言語モデル）: 「文脈の次に来る言葉」を確率予測。数千億の文章パターンから推論・翻訳・要約も実現
  • ハルシネーション: 事実でない情報を自信たっぷりに出力する現象。確率的生成の構造的特性
  • トークン: テキストの最小処理単位。日本語は英語より多くのトークンを消費。APIコストは従量課金
  • コンテキストウィンドウ: LLMが一度に処理できるトークン上限。「入る」≠「入れるべき」
  • モデルルーティング: タスクの難易度に応じて軽量/高性能LLMを使い分ける設計パターン

試験頻出ポイント

  • 識別/生成タスクは現在どちらもLLMで処理するのが主流（モデルルーティングで使い分け）
  • AIエージェントの性能はモデル選定だけで決まらない。重要なのはデータ整備
  • API費用はTCO（総所有コスト）の一部に過ぎない

1-2. AIエージェントの定義と構成要素

覚えること

  • ツールとしてのAI活用 vs エージェントとしてのAI活用: 1往復で道具的に使うか、目標を与えて業務プロセス全体を自律推進させるか
  • 三位一体モデル: 頭脳（LLM）/ 記憶（ナレッジベース・RAG）/ 手足（ツール連携・API/MCP）
  • 1つでも欠けると不完全（手足がなければ「高機能なFAQ検索」止まり）
  • 自律性4段階: 反応型 → 支援型 → 協働型 → 自律型
    • 反応型: Google翻訳のように入力に即反応
    • 支援型: AIが回答案を提示、人間が最終判断
    • 協働型: 定型業務はAI自動、複雑案件は人間にエスカレーション
    • 自律型: 目標を与えれば計画から実行まで完遂
  • 支援型と協働型の境界: AIが最終判断を含む意思決定を自律的に行うか

試験頻出ポイント

  • 「何を任せるか」と同じくらい「何を任せないか」が重要
  • 判断基準は「やり直しがきくか」「不可逆な操作か」

1-3. AIエージェントの起動タイプ

覚えること

  • 指示型: 人間がリアルタイムに指示。チャット入力・ボタンクリック
  • 定時型: スケジュール起動。「毎朝8時に週次レポート」など。導入効果が見えやすい
  • 条件型: イベント発生で起動。「CRMステータス変更で動く」など
  • 見分け方: AIエージェントに直接依頼したか？ Noなら条件型
  • 1つのエージェントが複数の起動タイプで運用されることは一般的
  • 条件型は「業務フローを変えずにAIを溶け込ませる」設計の鍵（形骸化リスク対策）

試験頻出ポイント

  • 起動タイプと自律性レベルは独立した設計判断
  • CRMへのデータ登録 → 自動メール生成は「条件型」（指示型ではない）

1-4. RPAとAIエージェントの違い

覚えること

  • RPA: ルールベース自動化。手順が完全に決まっている定型作業を高速・正確にこなす
  • AIエージェントとの本質的違い: 「思考や解釈を行う能力の有無」
  • RPAはルールが正しければ100%正確。AIエージェントは確率的でハルシネーションリスクあり
  • 使い分け3基準: 例外的判断が必要か / 入力が定型か / 例外の頻度
  • ハイパーオートメーション: 業務プロセスの各ステップを「定型処理」と「AI処理」に切り分けて最適配分
  • AIが「読み取り・判断」、定型処理が「システム操作」を担当する役割分担が基本構成

試験頻出ポイント

  • 既存業務をそのまま自動化せず、AI前提で業務プロセスを再設計する
  • 非構造化データの処理こそLLMの決定的優位

1-5. エージェントの接続標準 MCP

覚えること

  • API: ソフトウェア間の機能呼び出しの窓口。ツールごとに専用フォーマット
  • MCP（Model Context Protocol）: AIエージェントと外部ツールの接続を共通規格で行う仕組み。2024年11月Anthropic公開
  • MCPはAPIを置き換えるのではなく、APIの上に共通フォーマットを被せる
  • M×N問題: M個のモデル × N個のツールを個別接続すると組み合わせ爆発。MCPでM+Nに削減
  • MCPのもう一つの強み: ツール選択の自動化（LLMが必要なツールを自動判断）
  • 信頼できないMCPはセキュリティリスク。提供元確認必須

試験頻出ポイント

  • 接続方式判断基準は「今後の拡張計画があるか」
  • ストラテジストの役割は接続先一覧・追加予定・LLM切替可能性を整理してアーキテクトに渡すこと

1-6. AIエージェント導入の価値

覚えること

  • 定量的メリット: 工数削減・人件費削減・エラー率低下など数値化可能
  • 定性的メリット: 顧客体験向上・従業員体験向上など数値化困難だが重要
  • 経営層への報告フォーマット: 「定量的メリット」「定性的メリット」「リスクと対策」の3点セット
  • ROI: Return on Investment。投資対効果
  • TCO（Total Cost of Ownership）: 総所有コスト。API費用だけでなく構築・ナレッジ整備・監視・保守すべて含む
  • API費用はTCOのごく一部

試験頻出ポイント

  • ROIだけで投資判断を完結させない
  • 経営層には定量、現場には定性のメリットが響く（同じ価値を語り分ける）

1-7. AIエージェントのリスクと対策

覚えること

  • 4つのリスクカテゴリー:
    • 信頼性リスク: 出力や判断が正確でない（ハルシネーション）→ 対策: RAGで根拠付け
    • 形骸化リスク: 導入しても現場で使われない → 対策: 条件型起動・利用状況モニタリング
    • ブラックボックス化リスク: 野良エージェントが増え管理不能 → 対策: エージェント台帳
    • セキュリティ/倫理リスク: 情報漏えい・偏り・プロンプトインジェクション → 対策: 多層防御
  • プロンプトインジェクション: 悪意ある入力でAIの動作を本来意図と異なる方向に誘導する攻撃
  • 対策は入力フィルタリングだけでなく、出力制御・アクセス権限まで含む多層防御
  • バイアス: 学習・参照データの偏りが出力に反映されるリスク

試験頻出ポイント

  • リスクは独立せず相互に影響（信頼性低下→形骸化→ブラックボックス化の連鎖）
  • 判別の決め手:「精度の問題」=信頼性 /「人が使わない」=形骸化 /「誰も管理していない」=ブラックボックス /「悪意・偏り・倫理」=セキュリティ・倫理

1-8. 生成AIの発展トレンド

覚えること

  • 3つの進化軸:
    • エージェント化: AIを「実行できる」存在に。API連携・MCP・ブラウザ操作・フィジカルAI
    • ドメイン特化: AIに専門家としての深さを持たせる。RAG / ファインチューニング / パーソナライズ / 検索連携
    • モデル強化: モデル規模拡大 / マルチモーダル化 / 小型化・軽量化（SLM）/ 推論能力強化
  • SLM（Small Language Model）: 小さく速く低コスト。デバイス上で動作可能。LLMより精度が劣る傾向
  • マルチモーダルAI: テキスト・画像・音声・動画を統合処理
  • 推論モデル: 段階的に問題を整理しながら答えを導く。応答時間とコストが高い

試験頻出ポイント

  • 自社業務にトレンドが必要か判断する3基準: 該当する入力データがあるか / コストと精度のバランス / 現時点の性能で耐えるか
  • トレンドを暗記するのではなく「自社のこの業務に使えるか」を問う
